Эксклюзивный: общий name — открыт всегда один раздел
Нужен ли Griffincss сборщик?
Нет. Готовые .css подключаются тегом <link>; SCSS-исходники нужны только тем, кто собирает свою сборку с частью модулей.
Обязателен ли ресет?
Нет, он отдельным файлом и подключается по желанию. Поэтому каждый компонент задаёт box-sizing, font-family: inherit и обнуление полей сам — на чужой ресет он не рассчитывает.
Что будет без JavaScript?
Всё, кроме раскладок data-gr-layout: они и есть рантайм. Компоненты раскрытия работают без единой строки скрипта — этот аккордеон в том числе. 
<div class="gr-accordion">
  <details class="gr-accordion-item" name="faq">
    <summary class="gr-accordion-trigger">Вопрос</summary>
    <div class="gr-accordion-panel">Ответ</div>
  </details>
</div>

Эксклюзивность — атрибут, а не скрипт. Одинаковый name у соседних <details> заставляет браузер закрывать предыдущий раздел при открытии следующего. Ни одной строки CSS и ни одной строки JS на это не потрачено. Уберите name — разделы начнут открываться независимо, и это тоже рабочий режим.

Без обёртки — .gr-accordion-flush
Доставка
Два дня по городу, пять по стране.
Возврат
Четырнадцать дней без объяснения причин.

Анимация высоты — украшение поверх работающего раздела. Она включается только там, где браузер умеет интерполировать auto (interpolate-size: allow-keywords) и выбирать содержимое <details> селектором (::details-content). Не выполнено хотя бы одно условие — раздел раскрывается мгновенно, и это нормальное состояние, а не поломка: ни одного правила, скрывающего содержимое, за пределами @supports в модуле нет.

Утилиты

Почти полторы тысячи классов — отступы, цвета, типографика.

Разметка одна и та же — с атрибутом и без. Уберите data-gr-tabs или скрипт, и останутся три секции подряд и ряд ссылок, ведущих к ним якорями: страница читается сверху вниз, печатается целиком и работает без JS. С атрибутом griffincss-ui.js добавляет role="tablist", aria-selected, стрелки ← →, Home / End и roving tabindex, а неактивные панели прячет атрибутом hidden.

КлавишаЧто делает
← → ↑ ↓Соседняя вкладка; ряд замкнут в кольцо
Home / EndПервая и последняя доступные вкладки
TabУводит из ряда в содержимое панели, а не по всем вкладкам подряд

Roving tabindex. В порядке обхода остаётся одна вкладка — выбранная; у остальных tabindex="-1". Ряд из десяти вкладок иначе стоил бы десяти нажатий Tab на пути к содержимому. Панель получает tabindex="0", поэтому следующее нажатие приводит именно в неё.

Щелчок по вкладке-ссылке не уводит к якорю. Прыжок сдвинул бы ряд вкладок за верхний край экрана: человек нажал на заголовок и потерял его из виду. Скрипт отменяет переход и переключает панель на месте — а без скрипта якорь работает как якорь, и это правильное поведение для страницы без JS.

Во всю ширину — .gr-tabs-stretch
<div class="gr-tabs">
  <nav class="gr-tablist" aria-label="Разделы">
    <a class="gr-tab" href="#core" aria-current="page">Ядро</a>
    <a class="gr-tab" href="#ui">Компоненты</a>
  </nav>
  <section class="gr-tab-panel" id="core">…</section>
  <section class="gr-tab-panel" id="ui">…</section>
</div>

Панель прячет разметка, а не библиотека. В модуле нет правила .gr-tab-panel { display: none } — и не появится: оно убрало бы панель с экрана, но оставило бы её в порядке обхода Tab и в озвучке. Атрибут hidden убирает и то, и другое, поэтому скрытие остаётся делом разметки и скрипта, а не таблицы стилей.
